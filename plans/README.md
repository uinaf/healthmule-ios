## Findings considered and rejected

Recorded so they are not re-audited next run.

- **`AppModel` is 2,074 lines / "god object"** — rejected as framed. The file
  has one theme and its pure helpers (`SyncReadiness`,
  `SelectionReconciliationQueue`, `ObserverFlushQueue`, `SyncProgressState`) are
  already extracted and tested. The real cost is that it hosts *three
  independent epoch domains* (`operationEpoch`, `googleTransitionEpoch`,
  `healthRefreshEpoch`) in one mutable scope with no mechanical enforcement of
  which applies where. Splitting on line count would not address that;
  characterization tests would. See the maintenance note in plan 003.
- **`FileSyncStore` whole-file state rewrite / quadratic growth** — already
  decided and documented in `docs/decisions/sync-store-persistence.md`, status
  `migration-plan-required`.
- **HealthKit read-denial ambiguity** — intentional and documented; HealthKit
  does not disclose read-denial.
- **`escapedQueryValue` escaping only `\` and `'`** — correct; that is the
  complete escape set for the Drive query language's single-quoted literals.
- **Watch sync requests accepted without an origin check** — WatchConnectivity
  is OS-restricted to the paired same-team companion, the payload is
  schema-validated, and the handler is gated on `canRequestSync`.
- **`dependency-watch.yml` workflow-level `issues: write`** — cosmetic; the
  trigger set is `schedule` + `workflow_dispatch`, and the interpolated value is
  shell-quoted, not `${{ }}`-substituted into script text.
- **Several concurrency candidates that proved correct on close reading**:
  `LiveSyncCoordinator.acquireOperation`'s cancel/handoff interleavings,
  `ObserverFlushQueue.finish()`'s precondition, the `operationState` `didSet`
  epoch bump, and `BackfillDatePlanner`/`DayBoundaryStore` DST handling.
- **`@preconcurrency import HealthKit` / `WatchConnectivity`** — Apple SDK
  annotation gaps, not project debt. Re-check at each SDK bump.

## Audited but not planned

Real findings that did not make this batch. Re-surface them rather than
re-deriving them:

- `error.localizedDescription` is rendered in the UI at 11 sites in `AppModel`
  and can surface a staged filename (a health-activity date) in a screenshot.
- `ResultGate` is duplicated three times in the Google layer, one copy already
  drifted; no direct unit test of the continuation gate.
- A missing `daily/<date>.json` permanently bricks `FileSyncStore`; the only
  exit is a destructive full reset.
- Cancellation checks sit between the remote commit and the durable commit in
  `SyncEngine.uploadPending`, so a cancel can drop backoff and reauthorization
  blocks.
- `allDailyRecords()` re-reads and re-decodes every staged record 4-5× per
  reconcile, including on the background observer path.
- The VO₂ max query re-reads the whole history window per day of a backfill.
- Seven transitive Google pins (AppAuth, GTMSessionFetcher, …) are watched by
  nothing; the `swift` Dependabot entry is a no-op because `Package.swift` has
  no external dependencies.
- No formatter/linter and no `shellcheck` gate over the 18 shell scripts that
  form the entire tooling and release contract.
- The macOS `compile` CI job has no DerivedData or toolchain cache.
- `SyncEngine.reconcile(dates:)` is production-dead but is what the core test
  suite exercises; the production path (`stageDaily` + `retryPendingUploads`)
  has less core-level coverage.
- `loadUITestState()` ships unguarded in release builds, unlike the repo's other
  test-only surface which is `#if DEBUG`-gated.

## Direction options

Not problems — options for the maintainer, grounded in
`docs/specs/healthkit-drive-exporter.md`:

- Publish the daily JSON contract as a versioned JSON Schema with a changelog,
  validated against `Tests/Fixtures/` in `make test-core`. The product's whole
  purpose is a downstream reader, and that reader has no machine-checkable
  contract today.
- A "Sync Now" App Intent, so the user can automate export timing from
  Shortcuts. The Watch already triggers the same idempotent path.
- A Watch complication for last-successful-sync. R11 already defines exactly
  what the Watch may display, and `CompanionSyncSnapshot` already carries it.
- A "Verify Drive contents" action that lists by `appProperties` and requeues
  gaps, replacing the current sledgehammer (bumping the internal export-contract
  revision to force a full republish).
